# CHAT — Telegram account integration

## Target

FREEzzz CHAT can display the authenticated user's Telegram account dialogs through a server-side MTProto client:

- private chats
- groups
- supergroups
- channels
- bots
- unread counts
- latest message
- message history
- sending messages

Telegram Mini App initData is validated on the backend before any CHAT API operation. Telegram's documentation requires server-side validation of initData; initDataUnsafe is not trusted. citeturn0search0turn0search1

## Architecture

Mini App → CHAT UI → Telegram Chat Client Adapter → authenticated Render backend → MTProto → Telegram.

The browser never receives the Telegram user MTProto session.

## Deployment configuration still required

The Render service must have these Telegram application credentials:

- TELEGRAM_BOT_TOKEN — already used by the existing Mini App authentication service.
- TELEGRAM_API_ID
- TELEGRAM_API_HASH
- TELEGRAM_SESSION_SECRET — configured server-side.
- ALLOWED_ORIGIN=https://freezzgames.github.io

The API ID and API hash are Telegram application credentials and cannot be inferred or generated by the portal. They must come from Telegram application registration. GramJS uses these credentials for the MTProto user client. citeturn2search0turn2search3

## Important persistence note

The current Render service uses an encrypted session file. The encryption key is server-side and the browser never sees it. The current free Render service does not have a persistent disk configured, so an infrastructure restart/deploy can require Telegram account re-authorization. Before treating this as permanent production storage, attach durable storage or move encrypted session records to the existing Render Postgres database.

## User flow

1. Open CHAT in the Telegram Mini App.
2. Backend validates Telegram initData.
3. If the account is not connected, enter the Telegram phone number.
4. Telegram sends the login code.
5. Enter the code in CHAT.
6. If Telegram 2FA is enabled, enter the 2FA password.
7. Backend stores the encrypted MTProto StringSession server-side.
8. CHAT loads dialogs and message history.
9. Sending a message is proxied through the backend.
10. Disconnect logs the MTProto account out and deletes its stored session.

Telegram/GramJS supports user authorization with phone number, verification code, and optional 2FA password, and exposes the resulting StringSession for server-side persistence. citeturn2search0turn2search3

CHAT remains isolated from HOME, LIVE, GAME, RADIO and LIBRARY.
